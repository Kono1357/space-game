# 朔  场景层框架（纯文本模式）

> 玩家以一个 `@` 存在于世界里。**走到哪，哪就是界面。**
> 画面是一个 `<pre>` 里的纯文本，**零 Canvas、零像素操作、地图全是 ASCII 字符**。

**在线玩**：<https://kono1357.github.io/space-game/>（GitHub Pages，根目录的 `index.html` 会自动跳到产物 `space-text.html`）。
本地玩：用浏览器直接打开 `space-text.html`（自包含单文件，`file://` 就能跑）。

---

## 0 架构一页纸

```
  内容 content/space.json      只有数据：场景 / 人 / 对话 / 事件 / 数值 / 教程
      |
      |  Core.load():  normalize -> applyMod(按 id 合并) -> build(编译场景网格) -> validate(只报警不崩)
      |  build_space.py:  把「内容 + 引擎」编进一个自包含 HTML
      v
  内核 engine/space-core.js    Game: 世界状态 / tick / 对话 / 效果 / 视图 / 屏幕合成 / 存档
      v
  外壳 engine/space-textshell.js + space-textout.js
        键盘鼠标 -> 内核; 内核把世界+UI 合成成一张字符网格 -> 翻成 ASCII -> 塞进一个 <pre>
```

**开发进度 / 交接文档在 [`DEVLOG.md`](DEVLOG.md)**（做到哪了、下一步做什么、怎么验证、别踩哪些坑）。

**改动协议在 [`CONTRIBUTING.md`](CONTRIBUTING.md)**（必跑命令、改动类型文档对照表、AI 交付固定格式）。

**给 AI 读的项目说明书在 [`AI_CONTEXT.md`](AI_CONTEXT.md)**（定位 / 技术栈 / 功能状态 / 数据结构 / 代码架构 / 硬约束 / 术语，末尾还有一段 2000 字以内的精简上下文包，可以直接贴进新对话）。

四条不变量，每条都有测试盯着（`node tests/run_all.js`）：

| # | 不变量 | 谁守着 |
|---|---|---|
| 1 | **内核不认内容**：字句、数值、条件、效果全在数据里；内容里出现未注册的效果词 / 判定词会被点名 | `validate()` + `test_arch.js`（拿内容真实用到的词逐个对表） |
| 2 | **一切皆 id 皆可合并**：`SPACE_BLOCKS`(34) + `NESTED_BLOCKS`(5) 登记在册，append 永不覆盖原内容，patch 只改你写的字段 | `test_arch.js`（拿内容里每一个块实测「加一条，老的还在吗」） |
| 3 | **坏数据只降级、不崩**：载入期问题进 `report.errors/warnings`，运行期未知词只 warn 一次 | `test_world.js` 的负例组 + `tools/validate_space.py` |
| 4 | **存档 = 世界快照**：`world` 里每个字段要么进档，要么在「派生量 / 缓存 / 出站队列」白名单里（`vis` `npcPaths` `path` `kernelOps` `proj`） | `test_arch.js`（逐字段快照比对 + 白名单校验 + 随机数状态） |

## 1 快速开始

```bash
python build_space.py            # 生成 space-text.html
```

用浏览器打开 `space-text.html` 即可。产物是**一个自包含的 HTML**，没有任何外链资源。

挂上兵棋内核（可选）：

```bash
python build_space.py --kernel ..\zhanyi.json
```

装 mod 的两种方式：

1. 把 mod 文件夹丢进 `mods/`，再跑一次 `python build_space.py`；
2. 打开游戏按 **F2**：粘 JSON、或者直接选一个 `mod.json` 文件、或者点「填入示例模板」
   按「应用并重载」**立刻生效，而且不用重新构建、不用重开、进度不丢**（热加载）。
   粘过的 mod 存在浏览器里，下次打开还在；每个 mod 可以单独移除，也可以导出带走。

想从零写一个自己的 mod：`python tools/scaffold_mod.py 我的房间 --id my_room` 生成骨架（房间 + 门 + 人 + 对话 + 终端 + 宏 + 钩子 + 自己起的块），
照着 `_howToAdd` 改就行。能跑的样板就是 [`tools/starter_mod.json`](tools/starter_mod.json)。

**终端面板里没有装饰按钮**：走到终端按 `E`，面板底部 `[1] [2] [3] ` 每一个都是真动作
要么花资源（合金 / 口粮 / 药品 / 舰队）、要么花时间（1 小时 / 2 天），做完数值立刻变，
同一块面板会当场刷新（例：资源终端 `[1] 合金换口粮 -20+5`、舰队面板 `[1] 调一支舰队回防索尔 -1 舰队`）。

终端动作的结果会显示在面板标题右侧（flash）；长剧情 / 档案 / 日志全文按 `L` 打开可滚动的阅读弹层，任务与指令进度按 `M`。

**没有任何东西会自动弹出来**：走到 `T`（星图终端）旁边不会自己打开，走到 NPC 旁边他会挡路但不会开口，
都要按 `E`。想恢复「走到就自动触发」，在 `content/space.json` 的 `config` 里把
`autoInteract` / `autoNpcTalk` 设成 `true`（两级开关，物件上还得写 `"auto": true`）。

## 3 地图字符

**字符管形状，颜色管类别**（按 `C` 切彩色：地板退到暗部，门 / 交互物 / 你 亮起来）。
墙按走向轮廓化，地板按场景类型换字。

| 字符 | 含义 | | 字符 | 含义 |
|---|---|---|---|---|
| `-` `\|` `+` | 墙（按走向画；四角 / 丁字 / 十字是 `+`）| | `@` | 你（出生点，编译成地板） |
| `#` | 墙的端点、孤立结构、货架一类的家具 | | `K G S L Y` | NPC |
| `.` | 地板（空间站）| | `T R S > i w y q` | 终端 |
| `,` | 地表（行星表面）| | `! ? % & ~ ; : /` | 大厅里的门牌（通向哪）|
| `;` | 裂隙地面 | | `=` | 大厅结构 / 指挥台 / 船台 / 传送带 |
| `:` | 舰内地板 | | `h` | 座椅 / 铺位 |
| `'` | 殖民地地面 | | `[` | 货架 |
| `+` | 门（都是 3 格宽，亮黄）| | `^` | 岩石 / 障碍 |
| `*` | 记录点（亮黄）| | `O` `X` | 风蚀岩 / 污染结晶 |
| （空格）| 未探明：什么都看不见，比雾更暗 | | `>` | 穿梭机终端 / 光标 |

- **墙为什么是 `-` `|` `+`**：`shapeWalls()` 按四邻把「成行」的实心结构画成有走向的线，
  端点和孤立格留 `#`。所以**图例里「墙」统一列成 `#`**（类别字符），屏幕上是 `-` `|` `+` 的走向。
  门（`+`）算结构邻格，门口两侧的墙不会被当成端点。
- **地板按场景类型换字**：映射写在 `config.floorByType`（内容），内核不认识任何场景类型；
  没登记的类型用 `config.defaultFloor`。想给自己的场景换地面 = 加一个 preset + 一条映射。
- **未探明是空白**（`config.fogChar`）：靠背景色比「虚空」亮一档区分；走过但当前看不见的地方
  用暗色画出记忆中的地形。
- **小图不再重复描边**：场景自己有一圈墙（门不算漏）时就用它自己的墙，不再套第二层线框。

**标准字符写在 `config.defaultLegend` 里**，每个场景的 `legend` 盖在它上面。
也就是说：新房间只写自己特有的字符就行，`# . +` 这些不写也不会出错
漏写的字符会被当成**墙**，一张图可能整张变实心（见文末「踩过的坑」），所以校验器会直接报错。

## 5 开放契约

**三条铁律：内核不认内容  内容不写代码  一切皆 id 皆可合并。**

所有内容块都是「带 id 的列表」，mod 按 id 合并：

| `_op` | 意思 |
|---|---|
| 不写（默认 `append`） | 新增。id 已存在就跳过并警告，**绝不覆盖原内容** |
| `patch` | 只改你写的那几个字段 |
| `replace` | 整条替换 |
| `remove` | 删除（需在 manifest 里写 `"allowRemove": true`） |

`_append` 可以只往数组里加一条，不用重抄整张表：

```json
{ "id": "station_corridor", "_op": "patch",
  "_append": { "tileEdits": [{ "x": 0, "y": 6, "preset": "door" }],
               "exits": [{ "x": 0, "y": 6, "to": "mod_observatory" }] } }
```

### 加东西改哪里

| 想加 | 改哪 | 写几行 |
|---|---|---|
| 一个新房间 | `scenes` | 一张字符地图（自己特有的字符才要写 `legend`） |
| 一个新的人 | `npcs` + `schedules` | 2 条 |
| 一段新对话 | `dialogues` | 1 张节点图 |
| 一台新终端 | `interactables` + `views` | 2 条 |
| 一个新目的地 | `shuttles` | 1 条（穿梭机菜单自动多一项） |
| 一条新的世界规则 | `events` + `npcApproach` | 2 条 |
| 一个新的数值来源 | `projections` | 1 条（数值自动画到地图上） |
| 一种标准地图字符 | `config.defaultLegend` | 1 条（所有场景都能用，场景 legend 仍可覆盖） |
| 一种新的地面（按场景类型换字） | `presets` + `config.floorByType` | 2 条（preset 一条 + 类型映射一条） |

**「带 id 的列表」不是口号，是一张登记表**：内核里 `SPACE_BLOCKS` 列了 **40 个顶层列表块**
（场景 / 人 / 对话 / 物件 / 事件 / 事件链 / 上报规则 / 资源 / 科技 / 舰队 / 势力 / 遗物 / 任务 / 危机 ），
`NESTED_BLOCKS` 列了 **5 个嵌套列表**（`galaxy.nodes`、`techTree.list`、`techTree.branches`、
`diplomacy.actions`、`tutorial.steps`）。**只有登记过的块才会按 id 合并**，没登记就会掉进 deepMerge、
被你的一条数据把整块替换掉（踩过：往 `events` 里加一条，120 条全没了）。

- 嵌套块两种写法都行：`{"galaxy": {"nodes": [...]}}` 或 `{"galaxy.nodes": [...]}`。
- 块里的条目**必须有 id**（`id` 就是合并的把手），校验器会点名没有 id 的块。
- `test_arch.js` 不是抽查：它拿**内容里真实存在的每一个块**逐个做「追加一条，老的还在吗」。

### 内容层的三个扩展点（不用改引擎）

| 想干什么 | 用哪个 | 写法 |
|---|---|---|
| 把一串效果打包复用 | **宏** `macros` | 定义 `{"id":"my_hello","effects":[...]}`，调用 `{"type":"macro","id":"my_hello","params":{"who":"客人"}}`，内部用 `{args.who}` 取值；带 `condition` 时还能用判定词 `{"type":"macro_condition","id":"my_hello"}` 复用条件 |
| 挂在引擎已有的时刻上 | **钩子** `hooks` | `on` 取 `game_start` / `tick`(可带 `every`) / `day` / `enter_scene` / `interact` / `npc_talk` / `dialogue_end` / `build_done`；过滤器 `scene` `interactable` `npcId` `dialogue` `buildId` `event`；`once` / `priority` |
| 拦下默认行为 | **`stop`** | 钩子或物件的效果链里放 `{"type":"stop"}`，后面的效果和内建行为都不执行（做替换而不是加法） |

**37 个效果词 + 21 个判定词**，都是可组合原语；效果参数自动套模板（所以 `onSelect` 里可以直接写
`{ "type": "travel", "to": "{row.scene}" }`）。判定词里 `not` / `all` / `any` 可以互相嵌套。
未知的键原样保留，mod 可以往内容里塞自己的块。

视图的 `source` 可以读**任意路径**，包括你自己起的私有块（`space.myNotes.list`）
所以「加一种新数据 + 立刻在终端里看到它」也不需要改引擎。

### 装了 mod 不用重开

外壳用 `Game.reloadContent(built)` 热加载：世界状态、背包、进度都留着；
场景被删了就回退到起始场景，人没了就摘掉，位置不在可走格上就挪到旁边，并把这些写在日志里。

## 7 布局与自适应

**视口是固定的**（`config.viewW` / `viewH`，本作 = 88x24）：字号 / 分栏 / 相机全部按**视口**算，
**不按当前场景算**否则从 60x22 的房间走进 88x28 的地表，字号会跳、分栏会翻，画面就"割裂"了。
场景在视口里**偏移**：比视口小的（例如 52x16 的引擎室）**居中、四周留黑、还描一圈边框**；
比视口大的（中央大厅 64x36、殖民地指挥部 76x30）**滚动显示**，镜头跟着玩家、停在边界内，
状态行会显示 `视野 < > ^ v` 告诉你画面外还有内容。
门的判定跟外观一致：**3 格宽的门洞，任何一格踩上去都算这扇门**（不只中间那一格）。

**自适应以「看得见多少格」为目标**（`config.mapTargetCols` / `mapTargetRows`，默认 104x28），
而不是"只要装得下就放大"：先找**最大的、还能看见目标格数**的字号，如果连场景都装不下，
就退到"能装下整个场景的最大字号"。

字号是这样落到画面上的（`space-textout.js`）：

1. `applyFont()` 把 `bold Npx "Consolas"` **真的写到 `<pre>` 的 style 上**；
2. 用一个隐藏的 `<pre>`（同样的 font / line-height / margin / padding）量「100 列  2 行」，
   得到单格宽 = 宽/100、单格高 = 高/2  不能用 span 量，inline 元素的 rect 高度是字体内容高，
   不等于行距，会和 `<pre>` 的实际行高对不上；
3. 外壳用**两遍适配**跟随分栏（先按分栏算  问内核给不给分栏  不给就按"日志在下方"重算）。

实测（Node 里按 0.6em 字宽 / 1.15em 行高估算；真实浏览器里 Consolas 字宽约 0.55em，列数会更多）：

| 窗口 | 指挥中心 72x24 | 地表 88x28 |
|---|---|---|
| 1243x561 | 17px  124x28  有分栏  场景填 79%/92% | 16px  124x31  有分栏  97%/97% |
| 1576x761 | 23px  112x29  有分栏  88%/89% | 22px  121x30  有分栏  99%/100% |
| 1920x1080 | 30px  106x30  有分栏  94%/86% | 25px  128x37  有分栏  94%/80% |
| 820x600 | 12px  117x42  有分栏  84%/60% | 12px  117x42  无分栏  75%/78% |

嫌大嫌小按 `+` / `-`（偏移量会记住），按 `0` 复位。开不了侧栏时日志自动回退到地图下方。

**场景尺寸**：25 个场景合计 **40,424 格**。指挥中心 72x24、中央大厅 64x36（四面八门，中间是通的）、
船坞 80x26、地表 80x26~88x28。所有门都是 **3 格宽**（原来单格门太窄）。地图由程序生成后手工调过：大厅柱阵 / 基地隔间 / 走廊凹槽 / 元胞岩层四种风格，
不是空盒子。

**宽屏自动分栏**：屏幕够宽时，日志和「附近」挪到右侧栏，纵向空间全留给地图。
「附近」按**种类**合并（`# 货架 (10,23) x13`），不然一屋子货架会把列表刷爆。

## 7.5 地图规则与生成器

地图不是随手画的，有一套**硬规则**（`tools/map_rules.py`，预设地图和随机地图共用）：

| 规则 | 内容 |
|---|---|
| R1 边框完整 | 最外一圈除了门洞，不能出现可走格 |
| R2 门洞够宽 | 沿门那条边量，连通的门口 **>= 3 格** |
| R3 单连通 | 可走格只有一个连通区（不能有走不到的屋子）|
| R4 / R5 | 出口格可走；出口的落点也必须落在目标场景的可走格上 |
| R6 不糊大墙 | 室内实心块最大正方形 <= 3（野外放宽到 8）|
| R7 开敞率 | 可走格 / 总格 >= 55% |
| R9 / R10 / R11 | 宽高偶数且在 44~104 x 14~36；四角不开口；每张图至少一个出口 |

```bash
python tools/map_rules.py                       # 校验 content/space.json 里全部 25 张预设地图
python tools/gen_maps.py --check                # 同一套规则的生成器入口
python tools/gen_maps.py --types                # 看有哪些地图原型（station/colony/surface/ship/rift）
python tools/gen_maps.py --gen --type station --seed 7   # 按种子生成一张随机地图（JSON）
python tools/gen_maps.py --selftest 20          # 每种原型 x 多种子生成 + 全量校验

# 一步产出「能走」的随机站（标准 mod 形状，可直接丢进 mods/ 或粘进 F2）
python tools/scaffold_scene.py --scenes 3 --seed demo --wire --out mods/demo_station/mod.json
python tools/gen_maps.py --wire <file.json>      # 给已有场景接线（幂等：跑两次结果一样）
python tools/gen_maps.py --wire-selftest 6       # 接线自检：全门有 transition / 全图连通 / 幂等
python tools/gen_maps.py --check-engine <file>   # 拿引擎真跑：门能不能走 / 全图连通 / 落点可站
```

**自动接线 `--wire` 的规则**：先把「相邻场景」接成一条链保证**连通**（已经连通的跳过，不重复接），
再把剩下的门按「方向相对（NS / WE）> 门口坐标对齐」两两配掉；
每扇门的落点取门内侧最近的可走格；**已经有接线的门一律不覆盖**（冲突只警告）。
所以跑第二次不会有任何变化（幂等）。

生成器是**确定性**的（同一个 seed 出同一张图），出口先画门不接线，接线由上层内容决定；
`--selftest` 会把生成的每一张图丢回规则里验一遍，不合规直接失败。
`python tools/validate_space.py` 也已经把 R1~R11 并进去了。

**校验要包含 mod（2026-10-02 补的一道闸）**：

```bash
python tools/validate_space.py --mods-dir mods        # 把 mods/ 全并进来再校验
python tools/validate_space.py --mods 某个mod.json     # 只并某一个
```

以前校验器只吃 `content/space.json`、**看不见 mod**：拿一个 mod 文件喂它，它会一路输出
「场景 0 / 人 0 / 对话 0 …… 错误 0 / 警告 0」——**静默假通过**。玩家改坏了 mod，
校验器说没问题，进游戏才发现地图整片变实心。现在：

- 传 mod 文件当内容 → 明确拒绝并告诉你正确用法（不再假通过）；
- `--mods` / `--mods-dir` → 按引擎的语义合并（append / patch / replace / remove、
  `_append`、`priority`、嵌套块…全部一致），**校验合并后的结果**；
- mod 之间撞 id、没声明 `allowRemove` 就删除、条目缺 id 这类合并期问题也进结论；
- **`python build_space.py` 会自动跑这一步，有错误就不出产物**（逃生口 `--no-check`）。

合并语义由 `tools/space_merge.py` 实现，它和引擎逐字节一致 —— 这件事由
`tests/test_merge_parity.js`（同一批 mod 喂两边、比 JSON）和
`tests/test_maprules_parity.js`（90 个场景逐格比对规则矩阵与引擎编译结果）守着。
没有这两条，校验器的结论就只是「另一个程序的看法」而已。

**门的写法**：边框上的门要开**连着的 3 格**（基础内容里每个门都是 `##+++##`）。
只开 1 格会被判 R2「门太窄」—— 校验器以前看不见 mod，这个坑没人提醒，
`mods/example_mod` 就踩了（已修）。

## 7.6 事件  功能文本（情报板）

事件改的是 `counters` / `flags` / `world.pending`；**这些改动现在都能在终端里看见**，终端也能反过来触发事件。

| 谁 | 干什么 | 文件里的写法 |
|---|---|---|
| 情报终端 `intel_terminal` | 指挥中心 (50,6)，打开 **情报板** | `interactables` + `views` |
| 情报板 待处理情报 | 列出 `world.pending` 里的事件（名字 / 分类 / 该找谁），按优先级排 | 段落级 `provider: "pending_events"` |
| 情报板 事件链 | 每条链走到第几步、下一步是哪个事件 | 段落级 `provider: "chain_progress"` |
| 情报板 态势 | **活计数器**：当前 / 开局 / 变化（事件改过就标出来） | 段落级 `provider: "situation"` |
| 资源终端 | 「现场盘点（活数据）」+「账面基数（静态）」对照 | 同上 + 静态 `source` |
| 舰队终端 | 多了一行 `{counters.fleets}` / `{counters.pollution}` | `lines` 模板 |

情报板上的「调阅最新情报  一 / 二 / 三」会 `pending_set` 三条情报事件（`ev_intel_01..03`），
做完一条（写 `intel_N_done`）才解锁下一条；这三条事件的选项带**功能效果**：
`npc_post`（把测绘员调去登陆点）、`counter_add`、`set_tile`（在裂隙入口立标记）、`discover`。
点完动作面板会**当场刷新**（终端 -> 事件 -> 世界 -> 终端，一个闭环）。

段落级 provider 是这一轮加的：一个终端里可以「活数据段 + 静态文案段」混着排（`sections[].provider`）。

## 7.7 数值出口：舰队稀缺 + 科技解锁（R4 / R8）

内容够多之后，这一轮补的是**让数字真的卡住选择**（对应 `DESIGN.md` 第 9 节的 R4 / R8；纯 JSON，不动引擎）。

**舰队（R4）**：10 条模板化 `fleet` 类事件的根节点多了第 4 个选项「抽调一支舰队前出盯着（-1 舰队）」：
- 代价是**一支舰队**（不可再生，归零 = 败北「舰队尽没」）；
- 收益是 `data +1`、`morale +1`；
- 条件带 `not flag:home_guard`：如果你先在舰队终端按过「调一支舰队回防索尔」，这个选项**当场消失**，
  要恢复机动就得先花一个动作「解除回防」。这就是设计文档里「昨天那个选择的代价」。

**科技（R8）**：研究终端新增 4 个方向，`requires` 串成一条线：

```
裂隙探测(30)  初级净化(45)  区域净化(80)
                   局部封印(60)
```

- 每个方向都是「立项扣合金  每 20 tick 推进  到点结算」的同一套研究流程，完成后写日志、给提示、进存档；
- **星图终端**：「组织净化作业」要 `tech_purge1`，「封锁裂隙」要 `tech_rift_seal`；
- `tech_purge2` 解锁更强的「部署广域净化场 -60 合金  污染-3」。

这样 `techTree` 从「立项完发一点资源」变成「**科技是稀有数值的出口**」：不研究，污染压不下去、裂隙封不了。

## 7.9 生成世界：一个种子一个宇宙（mods/generated_world）

`space-text.html` 里除了 25 张手写地图，还编进了一个**程序生成的世界**（`mods/generated_world/mod.json`）：

- **18 个站点 / 55 张地图（含地下层）/ 18 条穿梭机 / 18 个星图节点**（另有 1 条全局「返回索尔空间站」），分成 4 个星区；站点原型 = 空间站 / 殖民地 / 地表 / 舰内 / 裂隙；
  （地图数随 seed 浮动：每站 2~3 张主图 + 1 层地下，`gw1/18` 是 55 张。第 2 期换了命名之后 RNG 流变了，原来是 64 张。）
- **不会卡关**：全局有「返回索尔空间站」目的地，旗舰舰桥和每个站点首图都有穿梭机终端；
- **每个站点都有站内内容**：2 个 NPC + 1 个专属建筑（补给站 / 粮仓 / 信标塔 / 拆解台 / 封印桩）+ 1 个采集点 + 随机遭遇 + 1 层地下矿洞（可反复开采）；
- 从空间站的**穿梭机终端**选目的地过去；每个站点内 2~3 张地图用门连成一片；
- 星图终端里能看到每个站点的**归属 / 舰队 / 污染**（群星式战略层的底稿）；
- 生成结果是标准 mod：F2 可以直接装，也可以整个换掉。

```bash
python tools/gen_world.py --seed gw1 --sites 18      # 写 mods/generated_world/mod.json
python tools/gen_world.py --seed 我的世界 --sites 32  # 换一个更大的宇宙
python tools/gen_world.py --selftest                 # 确定性 / 结构自检
```

地图生成沿用 `tools/gen_maps.py`（BSP 房间 / 走廊 / 岩层 + R1~R11 硬规则），所以「矮人要塞式」的随机地形
不是随便撒点：每张图都必须过边框、门宽、单连通、开敞率。站点、穿梭机、星图节点都由 seed 决定，**同 seed 同世界**。

### 名字是「谁起的」：`nameCultures`（2026-10-02）

站点名和 NPC 名**不是从一个全局音节池里摇出来的**，而是按**站点的归属派系**选一套语言：

| 语言 | 谁说 | 地名例子 | 人名例子 |
|---|---|---|---|
| 索尔残响语 | 残响议会 | 穹顶台-锚地 | 岩见 铜满 薇芙 石恩 |
| 帷幕礼典语 | 帷幕公约 / 静默教团 | 薄暮-中继站 / 灰烬阶-荒野 | 纱兰 暮妮 白娅 祷妮 |
| 共同体通用语 | 织女星共同体 / 南门二商团 | 织女台-中继站 | 商元 衡平 渡生 契平 |
| 铁之锻语 | 铁合唱 | 熔池环-穹顶 / 锻台-驿站 | 锻号 铁一 炉七 钢一 |
| 深渊啧语 | 深渊 | 断章冢-裂隙带 | 锈恩 **沉** **锈** 烛姆 |
| 故帝国官话 | 旧帝国残响 | — | 垣姆 帝斯 冕尔 **帝** |
| 边地土话 | 自由矿工 / 拾荒者联盟 | 矿脉场-殖民地 / 镐湾-穹顶 | 沙子 尘头 锈子 **锈** |

- 每套语言就是一组词表（`placeA` / `placeB` 地名用词，`personA` / `personB` 人名用字）；
  `personB` 里放空字符串就是「这个名字只有一个字」（深渊那套靠这个出单字名）。
- **类型词跟站点种类对得上**：裂隙带不会被叫成中继站。
- **和手写层共用一张命名表**：生成器起名时会先避开手写层已有的 48 个星系节点名，
  所以 `索尔` 不会被再起一遍；索尔残响语那套词就是照着手写层（凯尔 / 石川 / 长夜锚地）拟的，
  两层名字听起来才像一个宇宙。
- **加一套语言不用改代码**：往 `nameCultures.list` 里加一条就行，mod 也可以
  （`tests/fixtures/mod_new_culture.json` 就是活例子）。注意 **id 跟所有块共用一个命名空间**
  （引擎会查跨块重复），别用 `abyss` 这种派系 id，加个前缀最保险。

## 7.10 地形与群系：连贯，不是麻点（2026-10-02）

野外地图不再是「随机撒点」，而是**值噪声 + 分形叠加**出来的连贯地形，由**群系**决定形状与材质：

| 群系 | 图案 | 材质 | 谁说 |
|---|---|---|---|
| 岩脊 | 成团的山脊 | `^` 岩石 | 岩质 / 荒芜 / 铁质 / 结晶 |
| 沙丘 | 台地孤峰 | `^` | 荒漠 / 沙丘 |
| 熔岩沟 | 长条沟壑 | `~` 液面 | 火山 / 熔海 |
| 冰裂 | 长条裂 | `^` | 冰封 / 苔原 / 浮空 |
| 林间 | 成团树丛 | `%` 植被 | 丛林 / 苔沼 |
| 沼面 | 成团 | `~` | 海洋 / 毒气 / 气态 / 异常 |
| 废墟 | 正交残墙 | `^` | 碎裂 |
| 洞窟 | 成团 | `^` | 所有地下层（火山行星的地下是熔岩沟）|

- **行星类型决定地貌**：站点的 `planetType` 由生成器抽，写进场景；地貌名缀在 `ambient` 后面，走进去按 `X` 看得到。
- **连贯是可量化的**：用同样密度的白噪声做对照，比「最大连通实心块」——
  新地形 **130~735 格**，白噪声只有 **6~16 格**（差 20~100 倍）。`tests/test_terrain.js` 把这条钉死了。
- **规则不让步**：噪声天然造大山块，实测有 6 张图报 R6（实心方块上限 8）。
  `VISION` 明说不为生成器放宽规则，所以是**生成器守规矩** —— `break_big_masses()` 会把过大的实心块
  挖一条连得上的缝打穿（挖出来的必须是连通的通道，否则会被「只留最大连通区」封回去）。
- **群系字符写在场景自己的 `legend` 里**，不占 `config.defaultLegend`。
  原因见下面「踩过的坑」：`defaultLegend` 是**深度合并**进每个场景的，
  往里加一个别的场景已经用过的字符，会把那个场景的意思改掉。

## 7.11 战略层：舰队、殖民地、派别、行星（2026-10-02）

指挥中心多了一台**战略台**（字符 `&`），六个看板：

| 看板 | 看什么 |
|---|---|
| 舰队名册 | 在编几支 + 14 支有名字的舰队（舰级 / 状态 / 在哪 / 舰体 / 舰员）+ 34 个可用模块 |
| 殖民地看板 | 10 个殖民地的人口 / 士气 / 口粮 / 矿石 / 防御 —— **每天结算一次** |
| 内部派别 | 12 个派别与支持度（按支持度排序，会随殖民地与污染变） |
| 外交态势 | 10 个派系对你的**活态度**（-4 敌对 ~ +3 亲近）+ 30 条外交动作 |
| 行星志 | 18 种行星类型与危害 / 产出 |
| 作战室 | **派舰队打仗** |

这几块数据在第 4 期之前**只登记在内核的块表里，一次都没被读过** —— 内容写了 593 条，游戏里看不到。
现在它们有账可查了。

### 作战室：舰队派遣

三个目标，各有守备：**裂隙-7（2）· 铁砧（3）· 裂隙-3（4）**。

1. 「派 3 支舰队打 X」→ 真扣 3 支舰队，同时读出对手守备；
2. 进战斗视图，**当场比大小**；两个分支的按钮只会出现一个：
   - 我方 ≥ 守备 → **「接战（我方不少于守备）」**
   - 我方 < 守备 → **「硬打（我方少于守备）」**
3. **合金 → 舰队 → 打节点 → 回收合金**：舰队名册里有「轨道船坞整备 2 支舰队（-25 合金）」，这是唯一的造舰途径；
   攻击有**两个档位**：派 3 支 / 派 5 支强攻（舰队 ≥5 才出现）—— 守备 4 的目标只有强攻打得下来；
4. 打赢：节点归你、守备清零、回收合金 +15 与 1 支舰队、战役计数 +1、对方态度变差；
   打输：三支舰队折进去、污染 +2、民情 -4、对方守备 -1；也可以**撤退**（三支出去两支回来）。

支撑它的是两个新词（内核里各十几行）：`counter_cmp`（比较两个计数器）和
`galaxy_get`（把星系节点的字段读进计数器）。没有这两个词，内容层表达不了「我方 vs 敌方」。

### 外交态度驱动事件

`rel_<派系>` 是活计数器（开局按 `factions.attitude` 播种）。态度越过阈值就会有人找你：
帷幕公约态度 ≥3 会送来一封没署名的信；铁合唱 ≤-4 会灭掉锻炉的火、断你的合金。

### 战役

`mis_campaign`「深渊反攻」挂在 `gw_wars_ops` 上，按 `M` 看 0/3 的进度条。
拿下三个节点会有收束对话，打过一仗之后深渊会找上门。

## 10 和兵棋层的关系

原 `zhanyi.json` **一个字节都没动**。

```
 兵棋数据层（不动）
   RULE / TEXT / CONTENT          <- 舰队、外交、科技、事件、战斗
        |
        |  桥：game.opts.kernel（读）  +  effect "kernel"（写）
        v
 场景层
   SPACE = 场景 / 人 / 对话 / 物件 / 终端 / 穿梭机 / 投影 / 教程
```

- **读**：`build_space.py --kernel` 注入的 `ZHANYI_KERNEL` 会作为 `game.opts.kernel` 交给内核层，
  视图的 `"source": "kernel.xxx"` 和判定词 `kernel:` 都从这条路径读。
- **写**：`effect "kernel"` 把玩家的决定（`op` + `params`）推进 `world.kernelOps`，
  同时回调宿主外壳的 `onKernel`。`kernelOps` 是**出站队列**：由宿主或内核桥接层取走，
  不取走就一直在那儿（它不进存档，属「派生量 / 缓存 / 出站队列」白名单）。记录点终端的 `save` / `load` / `export` 就是外壳自己接下的那一档
  （落到 localStorage），其余 op 留着给兵棋内核的桥接层来拿。
- **投影**把内核数值画成地图上的字符：污染度 0/1/2/3  `.` `:` `%` `X`（X = 污染结晶，和裂隙里的结晶同一个字符）
- 视图的 `source` 可以直接读内核：`"source": "kernel.galaxy.nodes"`
